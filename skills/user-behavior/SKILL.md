# User Behavior

## Overview

Analyze repeated emotions and behavior loops in a domain. The goal is to understand what users want, fear, avoid, repeat, postpone, compare, or abandon.

## Workflow

1. Identify the user segment and context of use.
2. Map the user's job, emotion, trigger, action, reward, friction, and drop-off points.
3. Explain domain-specific behavior patterns instead of generic psychology.
4. Connect behavior to product design, messaging, onboarding, retention, and trust.
5. Suggest research questions and experiments to validate assumptions.

## Output Structure

Use this structure:

1. User Context
   - Who the user is
   - What situation triggers use
   - What emotional state they bring

2. Behavior Pattern Table
   - Pattern
   - Trigger
   - User emotion
   - Observable behavior
   - Product risk
   - Product response

3. Behavior Loops
   - Describe the core loop: trigger -> action -> reward -> next motivation.
   - Identify where the loop breaks.

4. Segment Differences
   - Explain how behavior differs by beginner vs expert, buyer vs user, high-risk vs low-risk user, or supply vs demand side.

5. PM Implications
   - UX choices
   - Messaging
   - Onboarding
   - Retention levers
   - Research questions

## Domain Pattern Examples

- Finance users feel anxiety, loss aversion, trust sensitivity, and fear of irreversible mistakes.
- Education users struggle with persistence, delayed rewards, identity, confidence, and time fragmentation.
- Games users seek immediate feedback, mastery, status, novelty, fairness, and social comparison.
- Commerce users compare options, seek reassurance, abandon under uncertainty, and react strongly to delivery or return friction.
- Healthcare users need trust, privacy, clarity, empathy, and help acting under stress.
- B2B users optimize for risk reduction, internal approval, workflow fit, and accountability.

## Quality Bar

- Avoid universal claims like "users want convenience" unless tied to domain context.
- Explain observable behaviors a PM could research or measure.
- Distinguish user, buyer, payer, and operator behavior when they differ.
- Connect behavior patterns to product decisions and metrics.
- Mark assumptions when the target segment is unclear.
- If the user writes in Korean, answer in natural Korean unless they request another language.
